## 1. 文档概述

本文档详细描述了基于CrewAI+LangChain构建的**四级角色多智能体协作系统**的技术实现方案，涵盖功能设计、业务逻辑、技术栈、核心代码实现、开发优先级、风险控制和扩展方向，为开发、测试和运维人员提供全面的技术参考。

- 实时过程检测与分级问题上报

## 3. 模块定位
多智能体协作模块是整个AI应用系统的**核心调度层**，负责将复杂任务分解为多个子任务，分配给不同角色的智能体执行，协调它们之间的通信和协作，监控执行过程，处理异常情况，并最终整合结果输出。

```
┌─────────────────┐
│   用户接口层    │ Web界面、API接口、移动端
└─────────┬───────┘
          │
┌─────────▼───────┐
│ 多智能体协作层  │ 本模块，核心调度与协作
└─────────┬───────┘
          │
┌─────────▼───────┐
│   基础能力层    │ LLM、工具链、向量存储、数据库
└─────────────────┘
```

## 4. 功能核心与详解
### 4.1 统一状态管理模块
**功能描述**：状态管理是多智能体系统的核心骨架，负责保障中枢与组员之间的状态一致性、任务可追溯性和故障可恢复性。

**核心能力**：
1. **状态分类与边界定义**：明确区分全局状态、角色专属状态和任务关联状态，避免状态混乱
2. **完整生命周期管理**：实现状态的初始化、流转、终止和清理的自动化流程
3. **乐观锁并发控制**：基于版本号实现状态更新，避免脏写和数据不一致
4. **混合存储方案**：热状态存储在Redis，冷状态和历史数据存储在PostgreSQL
5. **故障自动恢复**：系统重启后自动从持久化存储恢复所有状态
6. **状态变更事件通知**：状态变更时自动触发事件，通知相关订阅者

**设计原则**：
- 单一可信源：中枢Agent维护全局唯一可信状态，所有其他Agent的状态最终与中枢一致
- 最终一致性：非关键操作采用最终一致性模型，关键操作保证强一致性
- 增量同步：只同步变更的字段，减少数据传输量
- 幂等性：所有状态更新操作都是幂等的，支持重复执行

### 4.2 分级通信与事件系统
**功能描述**：提供可靠、高效、灵活的通信机制，支持Agent之间的同步指令和异步事件通知。

**核心能力**：
1. **双通道通信架构**：
    - 普通通道：基于Redis Pub/Sub的异步事件通知，用于一般消息传递
    - 紧急通道：基于gRPC的同步调用，用于重大问题上报和紧急指令下发
2. **事件主题划分**：按角色和事件类型划分主题，实现精准推送
3. **消息确认与重试**：所有消息都有确认机制，未确认消息自动重试
4. **消息序列化**：使用Protobuf进行序列化，保证高性能和跨语言兼容性
5. **流量控制与熔断**：实现限流和熔断机制，防止系统过载

**设计原则**：
- 解耦：通过事件机制解耦生产者和消费者
- 优先级：紧急消息优先处理，确保重大问题及时响应
- 可靠性：保证消息至少送达一次，避免消息丢失
- 可观测性：所有通信都有日志记录，便于问题排查

### 4.3 实时过程检测与分级问题上报
**功能描述**：实时监控每个Agent的执行过程，检测异常和问题，并根据问题等级自动上报给相应的处理角色。

**核心能力**：
1. **步骤级实时监控**：基于CrewAI回调机制，拦截每个Agent的每一步执行
2. **多维度检测规则**：支持错误关键词、执行时间、资源使用、输出质量等检测
3. **三级问题分级**：
    - 一般问题：记录到数据库，定期汇总分析
    - 严重问题：立即通知综合Agent，评估后上报领导
    - 重大问题：直接通知领导Agent，触发紧急任务终止
4. **问题自动分类与打标**：基于规则和大模型对问题进行自动分类和打标
5. **问题追踪与闭环**：跟踪每个问题的处理过程，直到解决

**设计原则**：
- 实时性：问题检测和上报尽可能实时，减少延误
- 准确性：降低误报率和漏报率，提高检测准确性
- 分级处理：不同等级的问题由不同角色处理，提高效率
- 可扩展性：支持自定义检测规则和问题处理流程

### 4.4 阶段评审与结果整合
**功能描述**：在任务执行过程中插入多个评审节点，对中间结果进行质量检查，确保最终结果符合要求。

**核心能力**：
1. **可配置评审节点**：支持在任务执行过程中插入任意数量的评审节点
2. **自动化评审**：基于大模型和规则对中间结果进行自动评审
3. **智能回退机制**：评审不通过时自动创建修正任务，分配给原组员
4. **结果聚合**：自动收集所有子任务结果，按照规则整合为最终输出
5. **优化建议生成**：定期分析问题数据，生成协作优化建议

**设计原则**：
- 质量优先：确保每个阶段的输出质量，避免问题积累到最后
- 效率平衡：评审节点数量和频率要合理，避免影响执行效率
- 可追溯性：记录所有评审结果和意见，便于追溯和改进
- 灵活性：支持自定义评审规则和流程

### 4.5 全生命周期成本管理
**功能描述**：实现从任务提交到完成的全生命周期成本管理，包括成本预估、实时追踪、预警控制和分析优化。

**核心能力**：
1. **多维度成本模型**：支持Token成本、工具调用成本、计算资源成本的统一计量
2. **精准Token计数**：使用模型官方分词器，支持流式输出的精确计数
3. **混合预估算法**：历史数据相似度匹配(60%) + 大模型辅助预估(40%)
4. **实时成本追踪**：每个步骤执行后立即更新成本，精确到分
5. **三级成本预警**：80%黄色预警、100%橙色预警、120%红色预警(自动终止)
6. **成本分析与优化**：自动分析成本构成，识别高成本环节，生成优化建议

**设计原则**：
- 准确性：成本计算和预估尽可能准确
- 实时性：成本数据实时更新，及时发现成本异常
- 可控性：支持成本上限设置和自动终止，防止成本超支
- 透明性：提供详细的成本报告，让用户清楚了解成本构成

### 4.6 任务调度与资源管理
**功能描述**：负责任务的分解、分配、调度和资源的动态管理，确保系统高效运行。

**核心能力**：
1. **智能任务分解**：将复杂任务自动分解为多个可执行的子任务
2. **基于能力的任务分配**：根据Agent的能力和负载情况，将任务分配给最合适的Agent
3. **任务依赖管理**：支持复杂的任务依赖关系，确保任务按正确顺序执行
4. **负载均衡**：动态调整任务分配，避免单个Agent过载
5. **资源动态调度**：根据系统负载动态调整资源分配，提高资源利用率

**设计原则**：
- 高效性：最大化系统吞吐量，最小化任务完成时间
- 公平性：合理分配任务和资源，避免某些Agent过度劳累
- 容错性：支持任务重试和重新分配，处理Agent故障
- 可扩展性：支持Agent的动态加入和退出，系统可水平扩展

## 5. 业务逻辑设计
### 5.1 角色职责与边界
本系统采用**领导-审查-综合-组员**四级角色架构，每个角色职责单一且边界清晰，避免职责重叠和越权操作。

#### 5.1.1 领导Agent（全局唯一，最高权限）
**核心职责**：全局决策、任务分解、资源调度、重大问题处理、系统配置管理
- 接收外部任务请求，验证任务合法性和可行性
- 将复杂任务分解为多个可执行的子任务，定义子任务之间的依赖关系
- 根据Agent的能力、负载和历史表现，将任务分配给最合适的Agent
- 处理重大问题，做出紧急决策，如任务终止、重新分配、资源调度等
- 审核综合Agent提交的优化建议，调整系统配置和协作策略
- 维护全局系统状态，监控所有Agent的健康状况和任务执行情况

**专属状态**：
```
- 全局任务队列：按优先级排序的待分配任务列表
- 角色能力矩阵：各Agent的能力评分、负载情况和历史表现
- 决策规则集：任务分配、异常处理、成本控制的规则配置
- 紧急问题队列：优先级最高的待处理重大问题
- 优化建议库：综合Agent提交的协作优化建议
- 系统配置：全局参数、阈值、开关等配置信息
```

**权限范围**：拥有所有状态的读写权限，可以执行所有系统操作。

#### 5.1.2 审查Agent（可多个，按领域划分）
**核心职责**：实时过程检测、输出质量校验、异常行为识别、问题分级上报
- 注册到领导Agent，声明自己的领域和能力
- 接收领导Agent的监控指令，开始监控指定任务的执行过程
- 实时分析组员Agent的执行日志、中间结果和资源使用情况
- 根据检测规则库，识别异常和问题，对问题进行分级
- 按照问题等级，将问题上报给相应的处理角色
- 任务完成后，生成检测报告，提交给综合Agent

**专属状态**：
```
- 监控任务列表：当前正在监控的所有执行中任务
- 检测规则库：按任务类型和领域定义的实时检测规则
- 问题分级标准：一般问题/严重问题/重大问题的判定阈值
- 实时检测日志：所有检测到的问题记录
- 异常行为模型：用于识别Agent异常行为的特征库
- 负载情况：当前正在处理的监控任务数量
```

**权限范围**：只能读取任务执行状态和中间结果，不能修改任务状态和执行流程。

#### 5.1.3 综合Agent（全局唯一，结果中枢）
**核心职责**：阶段评审、问题汇总分析、结果整合、优化建议生成
- 接收审查Agent上报的一般和严重问题，进行汇总和分析
- 在预设的阶段节点，对中间结果进行评审，决定是否继续执行
- 收集所有子任务的结果，按照规则整合为最终输出
- 定期分析问题数据和执行情况，生成协作优化建议
- 将优化建议和严重问题上报给领导Agent
- 维护评审历史和问题数据库，为系统优化提供数据支持

**专属状态**：
```
- 阶段评审计划：各任务的评审节点和标准
- 待评审成果队列：等待阶段评审的中间成果
- 问题汇总库：所有一般和严重问题的汇总分析
- 优化建议生成器：基于问题数据生成协作优化建议
- 评审历史记录：所有阶段评审的结果和意见
- 依赖关系图：子任务之间的依赖关系
- 中间结果缓存：已完成的子任务结果缓存
```

**权限范围**：可以读取所有任务状态和结果，可以修改任务的评审状态和综合状态。

#### 5.1.4 组员Agent（多个，按能力划分）
**核心职责**：具体任务执行、工具调用、中间结果生成、状态上报
- 注册到领导Agent，声明自己的能力和资源情况
- 接收领导Agent分配的任务，执行具体的任务逻辑
- 调用外部工具和服务，完成任务所需的操作
- 实时上报执行进度、中间结果和状态变化
- 接收综合Agent的评审意见，修正任务结果
- 任务完成后，提交最终结果给综合Agent

**专属状态**：
```
- 本地任务队列：等待执行的任务列表
- 当前任务状态：正在执行的任务的详细状态
- 执行环境状态：运行环境的配置和健康状况
- 工具调用记录：所有外部工具的调用记录和结果
- 执行上下文：任务执行的上下文信息
- 资源使用情况：CPU、内存、GPU等资源的使用情况
```

**权限范围**：只能读取和修改自己分配的任务的执行状态，不能访问其他Agent的任务和状态。

### 5.2 核心业务流程
#### 5.2.1 主流程：任务从提交到完成
```
1. 任务提交：用户通过API或界面提交任务请求
2. 任务接收：领导Agent接收任务，验证任务合法性
3. 全局成本预估：领导Agent预估任务总成本，检查是否超过用户预算
4. 任务分解：领导Agent将复杂任务分解为多个子任务，定义依赖关系
5. 子任务成本预估：领导Agent预估每个子任务的成本，设置成本上限
6. 任务分配：领导Agent根据Agent的能力和负载，将子任务分配给合适的组员
7. 监控注册：审查Agent注册到对应任务，开始实时监控
8. 任务执行：组员Agent执行任务，实时上报进度和中间结果
9. 实时检测：审查Agent实时分析执行过程，检测异常和问题
10. 阶段评审：到达预设评审节点时，综合Agent对中间结果进行评审
    - 评审通过：通知组员继续执行下一阶段
    - 评审不通过：通知组员修正后重新提交
11. 子任务完成：组员Agent完成子任务，提交结果给综合Agent
12. 结果整合：综合Agent收集所有子任务结果，整合为最终输出
13. 最终审核：领导Agent对最终结果进行审核
14. 结果返回：将最终结果返回给用户
15. 成本核算：生成详细的成本报告，记录到数据库
16. 优化分析：综合Agent分析本次任务的执行情况，生成优化建议
```

#### 5.2.2 实时过程检测流程
```
1. 任务分配：领导Agent将任务分配给组员Agent
2. 监控启动：领导Agent通知对应领域的审查Agent开始监控该任务
3. 流连接建立：审查Agent与组员Agent建立日志流和中间结果流连接
4. 实时分析：审查Agent对每一条日志和每一个中间结果进行实时分析
5. 问题检测：根据检测规则库，识别异常和问题
6. 问题分级：对检测到的问题进行分级（一般/严重/重大）
7. 问题上报：
    - 一般问题：上报给综合Agent，记录到问题数据库
    - 严重问题：立即上报给综合Agent，综合Agent评估后上报领导
    - 重大问题：直接通过紧急通道上报给领导Agent
8. 任务完成：组员Agent完成任务，通知审查Agent
9. 监控停止：审查Agent停止监控，生成检测报告提交给综合Agent
```

#### 5.2.3 阶段评审流程
```
1. 阶段到达：组员Agent完成当前阶段的任务，提交中间结果给综合Agent
2. 评审触发：综合Agent收到中间结果，触发阶段评审
3. 数据收集：综合Agent收集该阶段的执行日志、检测报告和中间结果
4. 自动化评审：综合Agent使用大模型和规则对中间结果进行自动评审
5. 评审结果：
    - 通过：通知组员Agent继续执行下一阶段
    - 不通过：生成修正意见，通知组员Agent修正后重新提交
6. 重试检查：检查该阶段的评审失败次数
    - 未超过最大重试次数：允许组员重新提交
    - 超过最大重试次数：升级为严重问题，上报领导Agent
7. 评审记录：记录评审结果和意见，保存到评审历史数据库
```

#### 5.2.4 分级问题处理流程
```
1. 问题检测：审查Agent检测到问题
2. 问题分级：
    ├─ 一般问题：
    │   1. 上报给综合Agent
    │   2. 综合Agent记录到问题数据库
    │   3. 定期汇总分析，生成优化建议
    ├─ 严重问题：
    │   1. 立即上报给综合Agent
    │   2. 综合Agent评估问题影响
    │   3. 通知相关Agent采取临时措施
    │   4. 上报给领导Agent
    │   5. 领导Agent做出决策，调整执行策略
    └─ 重大问题：
        1. 直接通过紧急通道上报给领导Agent
        2. 领导Agent立即终止相关任务
        3. 通知综合Agent停止后续流程
        4. 释放相关资源
        5. 评估问题影响，决定重新分配或取消任务
```

#### 5.2.5 紧急任务终止流程
```
1. 重大问题上报：审查Agent检测到重大问题，立即上报给领导Agent
2. 任务终止决策：领导Agent确认问题严重性，做出终止任务的决策
3. 终止指令下发：领导Agent向所有相关Agent发送任务终止指令
4. 执行终止：
    - 组员Agent：停止任务执行，保存当前状态
    - 审查Agent：停止监控，生成终止报告
    - 综合Agent：停止后续流程，保存已完成的结果
5. 资源释放：释放任务占用的所有资源（CPU、内存、GPU、文件句柄等）
6. 状态更新：更新任务状态为"已终止"，记录终止原因和时间
7. 问题处理：领导Agent根据问题类型，决定重新分配任务或取消任务
8. 通知用户：将任务终止的原因和处理结果通知用户
```

#### 5.2.6 协作优化闭环流程
```
1. 数据收集：综合Agent定期收集所有任务的执行数据、问题数据和评审数据
2. 数据分析：对收集到的数据进行统计分析，识别高频问题和薄弱环节
3. 原因分析：使用大模型分析问题产生的根本原因
4. 建议生成：根据分析结果，生成具体的协作优化建议
5. 建议提交：将优化建议提交给领导Agent
6. 建议审核：领导Agent审核优化建议，决定是否采纳
7. 策略调整：采纳的建议，更新系统配置和协作策略
8. 效果监控：监控优化后的系统表现，评估优化效果
9. 持续改进：根据效果评估结果，进一步调整和优化
```

### 5.3 状态机设计
#### 5.3.1 全局任务状态机
```

- 已完成：任务已完成，结果已返回
- 已终止：任务被紧急终止
- 已取消：任务被用户或系统取消
- 已归档：任务已完成超过7天，已归档到冷存储

状态转换规则：

2. 待分配 → 已分配：领导Agent将任务分配给组员
3. 已分配 → 执行中：组员Agent开始执行任务
```

### 5.4 跨角色交互逻辑
#### 5.4.1 交互模式
系统采用三种交互模式，满足不同场景的需求：
1. **指令式交互**：领导Agent向其他角色发送指令，如任务分配、暂停、终止等。采用同步gRPC调用，保证指令可靠送达。
2. **事件式交互**：角色状态变更或发生事件时，向相关角色发送事件通知。采用异步Redis Pub/Sub，解耦生产者和消费者。
3. **请求-响应式交互**：角色之间的同步请求，如获取任务详情、查询依赖状态等。采用同步gRPC调用。

#### 5.4.2 核心交互流程
**领导Agent ↔ 组员Agent**：
- 领导 → 组员：任务分配指令、暂停指令、恢复指令、终止指令
- 组员 → 领导：任务进度上报、任务完成通知、任务失败通知、资源使用情况上报

**领导Agent ↔ 审查Agent**：
- 领导 → 审查：开始监控指令、停止监控指令
- 审查 → 领导：重大问题上报、检测完成通知

**领导Agent ↔ 综合Agent**：
- 领导 → 综合：开始综合指令、停止综合指令、系统配置更新通知
- 综合 → 领导：严重问题上报、优化建议提交、综合完成通知

**审查Agent ↔ 综合Agent**：
- 审查 → 综合：一般问题上报、严重问题上报、检测报告提交
- 综合 → 审查：检测规则更新通知

**综合Agent ↔ 组员Agent**：
- 综合 → 组员：评审结果通知、修正意见通知
- 组员 → 综合：中间结果提交、最终结果提交

#### 5.4.3 事件主题定义
| 事件主题 | 发布者 | 订阅者 | 描述 |
|---------|--------|--------|------|
| `events.leader.task_assigned` | 领导Agent | 组员Agent、审查Agent | 任务已分配 |
| `events.leader.task_terminated` | 领导Agent | 所有Agent | 任务已被终止 |
| `events.worker.task_completed` | 组员Agent | 综合Agent | 任务已完成 |
| `events.worker.task_failed` | 组员Agent | 领导Agent、审查Agent | 任务执行失败 |
| `events.reviewer.problem_detected` | 审查Agent | 综合Agent | 检测到一般/严重问题 |
| `events.reviewer.critical_problem` | 审查Agent | 领导Agent | 检测到重大问题 |
| `events.integrator.review_completed` | 综合Agent | 组员Agent | 阶段评审完成 |
| `events.integrator.integration_completed` | 综合Agent | 领导Agent | 结果整合完成 |
| `events.integrator.optimization_suggestion` | 综合Agent | 领导Agent | 提交优化建议 |

## 6. 技术栈选型与架构设计
### 6.1 整体分层架构
本系统采用**四层分层架构**，各层职责单一，通过标准化接口交互，便于独立开发、测试和部署。

```
┌─────────────────────────────────────────────────────────┐
│ 接入层 (Access Layer)                                    │
│  REST API / gRPC API / WebSocket / 消息队列消费者        │
├─────────────────────────────────────────────────────────┤
│ 核心层 (Core Layer)                                      │
│  领导Agent / 审查Agent / 综合Agent / 组员Agent          │
│  状态管理器 / 通信管理器 / 事件管理器 / 任务调度器       │
│  成本管理器 / 检测引擎 / 评审引擎 / 优化引擎             │
├─────────────────────────────────────────────────────────┤
│ 基础能力层 (Foundation Layer)                            │
│  LLM统一接口 / 工具调用框架 / 向量存储 / 文档加载器     │
│  缓存服务 / 序列化服务 / 加密服务 / 日志服务             │
├─────────────────────────────────────────────────────────┤
│ 基础设施层 (Infrastructure Layer)                        │
│  Redis / PostgreSQL / Kafka / Prometheus / Grafana      │
│  Docker / Kubernetes / 云服务                            │
└─────────────────────────────────────────────────────────┘
```

#### 6.1.1 接入层
负责接收外部请求，提供多种接入方式，将请求转发给核心层处理，并返回结果。
- **REST API**：提供HTTP接口，用于任务提交、状态查询、结果获取等
- **gRPC API**：提供高性能RPC接口，用于内部服务之间的通信
- **WebSocket**：提供实时推送服务，用于任务进度和状态的实时通知
- **消息队列消费者**：从消息队列中接收异步任务请求

#### 6.1.2 核心层
系统的核心，实现多智能体协作的所有业务逻辑。
- **Agent集群**：领导、审查、综合、组员四种角色的Agent实例
- **核心管理器**：状态、通信、事件、任务调度等核心管理组件
- **业务引擎**：检测、评审、成本、优化等业务逻辑引擎

#### 6.1.3 基础能力层
为核心层提供通用的基础能力，屏蔽底层技术细节。
- **LLM统一接口**：封装不同大模型的API，提供统一的调用接口
- **工具调用框架**：提供标准化的工具调用接口，支持工具的注册和管理
- **向量存储**：提供向量存储和检索能力，用于知识检索和上下文管理
- **通用服务**：缓存、序列化、加密、日志等通用服务

#### 6.1.4 基础设施层
提供系统运行所需的基础设施服务。
- **数据存储**：Redis用于实时状态存储，PostgreSQL用于持久化数据存储
- **消息队列**：Kafka用于异步事件通知和任务队列
- **监控告警**：Prometheus用于指标采集，Grafana用于可视化和告警
- **容器编排**：Docker和Kubernetes用于服务的部署和管理

### 6.3 核心模块设计
#### 6.3.1 状态管理模块
**设计目标**：提供全局一致、高性能、高可靠的状态管理服务。

**核心组件**：
1. **状态存储引擎**：
    - Redis存储热状态：在线Agent状态、执行中任务状态、实时指标
    - PostgreSQL存储冷状态：已完成任务、历史日志、归档数据
    - 自动冷热数据交换：任务完成后自动从Redis迁移到PostgreSQL
2. **并发控制引擎**：
    - 基于版本号的乐观锁：更新状态时检查版本号，不匹配则重试
    - 分布式锁：使用Redis Redlock实现，用于任务分配、状态更新等关键操作
3. **状态同步引擎**：
    - 增量同步：只同步变更的字段，减少数据传输量
    - 事件驱动同步：状态变更时自动发布事件，通知相关订阅者
    - 定期全量同步：每小时进行一次全量同步，确保最终一致性
4. **故障恢复引擎**：
    - 系统重启时自动从持久化存储恢复所有状态
    - 支持状态快照和回滚

#### 6.3.2 通信管理模块
**设计目标**：提供可靠、高效、灵活的通信服务，支持同步和异步通信模式。

**核心组件**：
1. **gRPC通信引擎**：
    - 实现所有同步RPC接口

## 7. 具体技术实现

### 7.1 通用Agent基类实现
所有Agent的抽象基类，提供通用的生命周期、状态管理、通信和事件处理能力。

```python
import asyncio
import json
import logging
from abc import ABC, abstractmethod
from datetime import datetime
from typing import Any, Callable, Dict, List, Optional

import grpc
from redis.asyncio import Redis

from .proto import agent_pb2, agent_pb2_grpc
from .state_manager import StateManager
from .communication_manager import CommunicationManager
from .event_manager import EventManager

logger = logging.getLogger(__name__)

class BaseAgent(ABC):
    """所有Agent的抽象基类"""
    
    def __init__(
        self,
        agent_id: str,
        agent_type: str,
        capabilities: List[str],
        central_address: str,
        redis_client: Redis,
    ):
        self.agent_id = agent_id
        self.agent_type = agent_type
        self.capabilities = capabilities
        self.central_address = central_address
        
        # 核心管理器依赖注入
        self.state_manager = StateManager(redis_client)
        self.communication_manager = CommunicationManager(central_address)
        self.event_manager = EventManager(redis_client)
        
        # 运行时状态
        self.state: Optional[Dict[str, Any]] = None
        self.running = False
        self.paused = False
        
        # 事件回调注册表
        self.event_handlers: Dict[str, List[Callable]] = {}
        self._register_default_event_handlers()

    async def start(self) -> None:
        """启动Agent生命周期"""
        logger.info(f"启动Agent {self.agent_id} [{self.agent_type}]")
        
        # 初始化状态
        self.state = await self._init_state()
        
        # 注册到中枢
        await self._register_to_central()
        
        # 启动核心服务
        await self.communication_manager.start(self)
        await self.event_manager.start()
        
        self.running = True
        
        # 启动主循环
        asyncio.create_task(self._main_loop())
        logger.info(f"Agent {self.agent_id} 启动完成")

    async def stop(self) -> None:
        """停止Agent生命周期"""
        logger.info(f"停止Agent {self.agent_id}")
        
        self.running = False
        
        # 注销从中枢
        await self._unregister_from_central()
        
        # 停止核心服务
        await self.communication_manager.stop()
        await self.event_manager.stop()
        
        logger.info(f"Agent {self.agent_id} 已停止")

    async def pause(self) -> None:
        """暂停Agent执行"""
        logger.info(f"暂停Agent {self.agent_id}")
        self.paused = True
        await self.update_state({"status": "已暂停"})

    async def resume(self) -> None:
        """恢复Agent执行"""
        logger.info(f"恢复Agent {self.agent_id}")
        self.paused = False
        await self.update_state({"status": "运行中"})

    @abstractmethod
    async def _init_state(self) -> Dict[str, Any]:
        """初始化Agent专属状态，由子类实现"""
        return {
            "id": self.agent_id,
            "version": 1,
            "agent_type": self.agent_type,
            "capabilities": self.capabilities,
            "status": "未注册",
            "created_at": datetime.now().isoformat(),
            "updated_at": datetime.now().isoformat(),
        }

    async def _register_to_central(self) -> None:
        """注册到领导Agent中枢"""
        response = await self.communication_manager.call_leader(
            "register_agent",
            {
                "agent_id": self.agent_id,
                "agent_type": self.agent_type,
                "capabilities": self.capabilities,
                "state": self.state,
            }
        )
        
        if not response["success"]:
            raise RuntimeError(f"Agent注册失败: {response['message']}")
        
        self.state["status"] = "已注册"
        logger.info(f"Agent {self.agent_id} 成功注册到中枢")

    async def _unregister_from_central(self) -> None:
        """从中枢注销"""
        await self.communication_manager.call_leader(
            "unregister_agent", {"agent_id": self.agent_id}
        )
        logger.info(f"Agent {self.agent_id} 已从中枢注销")

    async def update_state(self, updates: Dict[str, Any]) -> bool:
        """更新Agent状态（乐观锁实现）"""
        if not self.state:
            return False
        
        old_version = self.state["version"]
        changed_fields = []
        
        # 应用更新
        for key, value in updates.items():
            if key in ["id", "created_at"]:
                continue
            if self.state.get(key) != value:
                self.state[key] = value
                changed_fields.append(key)
        
        if not changed_fields:
            return True
        
        # 更新版本和时间
        self.state["version"] += 1
        self.state["updated_at"] = datetime.now().isoformat()
        
        # 持久化到状态管理器
        success = await self.state_manager.update_agent_state(
            self.agent_id, self.state, old_version
        )
        
        if success:
            # 发布状态变更事件
            await self.event_manager.publish(
                f"events.agent.{self.agent_type}.state_changed",
                {
                    "agent_id": self.agent_id,
                    "old_version": old_version,
                    "new_version": self.state["version"],
                    "changed_fields": changed_fields,
                    "timestamp": datetime.now().isoformat(),
                }
            )
        
        return success

    async def _main_loop(self) -> None:
        """Agent主循环"""
        while self.running:
            if self.paused:
                await asyncio.sleep(1)
                continue
            
            try:
                await self._run_once()
            except Exception as e:
                logger.error(f"主循环异常: {str(e)}", exc_info=True)
                await asyncio.sleep(1)

    @abstractmethod
    async def _run_once(self) -> None:
        """执行一次主循环逻辑，由子类实现"""
        pass

    def register_event_handler(self, event_type: str, handler: Callable) -> None:
        """注册事件处理器"""
        if event_type not in self.event_handlers:
            self.event_handlers[event_type] = []
        self.event_handlers[event_type].append(handler)

    def _register_default_event_handlers(self) -> None:
        """注册系统默认事件处理器"""
        self.register_event_handler("task_assigned", self._on_task_assigned)
        self.register_event_handler("task_cancelled", self._on_task_cancelled)
        self.register_event_handler("pause_command", lambda e: self.pause())
        self.register_event_handler("resume_command", lambda e: self.resume())
        self.register_event_handler("stop_command", lambda e: self.stop())

    @abstractmethod
    async def _on_task_assigned(self, event: Dict[str, Any]) -> None:
        """处理任务分配事件，由子类实现"""
        pass

    async def _on_task_cancelled(self, event: Dict[str, Any]) -> None:
        """处理任务取消事件，默认实现"""
        task_id = event["task_id"]
        logger.info(f"任务 {task_id} 已被取消")
```

### 7.2 核心角色Agent实现
#### 7.2.1 领导Agent实现
全局唯一决策中心，负责任务分解、分配和重大问题处理。

```python
class LeaderAgent(BaseAgent):
    def __init__(self, llm, redis_client, cost_manager, *args, **kwargs):
        super().__init__(*args, agent_type="leader", **kwargs)
        self.llm = llm
        self.cost_manager = cost_manager
        self.critical_problem_queue = asyncio.Queue()
        self.task_queue: List[Dict[str, Any]] = []

    async def _init_state(self) -> Dict[str, Any]:
        base_state = await super()._init_state()
        return {
            **base_state,
            "pending_task_count": 0,
            "critical_problem_count": 0,
            "optimization_suggestion_count": 0,
            "system_load": 0.0,
        }

    async def _run_once(self) -> None:
        # 处理任务队列
        await self._process_task_queue()
        
        # 更新系统状态
        await self.update_state({
            "pending_task_count": len(self.task_queue),
            "critical_problem_count": self.critical_problem_queue.qsize(),
            "system_load": await self._calculate_system_load(),
        })
        
        await asyncio.sleep(1)

    async def start_critical_problem_consumer(self) -> None:
        """启动重大问题处理协程"""
        while self.running:
            problem = await self.critical_problem_queue.get()
            try:
                await self._process_critical_problem(problem)
            except Exception as e:
                logger.error(f"处理重大问题失败: {str(e)}", exc_info=True)
            finally:
                self.critical_problem_queue.task_done()

    async def submit_task(self, task_request: Dict[str, Any]) -> str:
        """提交新任务入口"""
        # 1. 全局成本预估
        cost_estimate = await self.cost_manager.estimate_task_cost(
            task_request["description"], task_request["type"]
        )
        
        # 2. 检查预算
        if "budget" in task_request and cost_estimate["total"] > task_request["budget"]:
            raise ValueError(f"任务预估成本¥{cost_estimate['total']:.4f}超过预算¥{task_request['budget']:.4f}")
        
        # 3. 创建任务
        task_id = f"task_{datetime.now().strftime('%Y%m%d%H%M%S')}_{id(task_request)}"
        task = {
            "id": task_id,
            "version": 1,
            "task_type": task_request["type"],
            "description": task_request["description"],
            "expected_output": task_request["expected_output"],
            "parameters": task_request.get("parameters", {}),
            "status": "待分配",
            "priority": task_request.get("priority", 1),
            "estimated_cost": cost_estimate["total"],
            "cost_limit": task_request.get("cost_limit", cost_estimate["total"] * 1.2),
            "current_cost": 0.0,
            "dependencies": task_request.get("dependencies", []),
            "created_at": datetime.now().isoformat(),
            "updated_at": datetime.now().isoformat(),
        }
        
        # 4. 持久化任务状态
        await self.state_manager.create_task_state(task)
        
        # 5. 加入任务队列
        self.task_queue.append(task)
        logger.info(f"新任务 {task_id} 已提交，预估成本¥{cost_estimate['total']:.4f}")
        
        return task_id

    async def _process_task_queue(self) -> None:
        """处理任务队列，分配任务给合适的组员"""
        if not self.task_queue:
            return
        
        # 获取所有可用组员
        available_workers = await self.state_manager.list_agents_by_type_and_status(
            "worker", "运行中"
        )
        
        if not available_workers:
            logger.warning("没有可用的组员Agent")
            return
        
        # 按优先级排序任务
        self.task_queue.sort(key=lambda t: (-t["priority"], t["created_at"]))
        
        # 分配任务
        for task in self.task_queue[:]:
            # 筛选具备能力的组员
            suitable_workers = [
                w for w in available_workers
                if task["task_type"] in w["capabilities"]
            ]
            
            if not suitable_workers:
                logger.warning(f"没有适合执行任务 {task['id']} 的组员")
                continue
            
            # 选择负载最低的组员
            selected_worker = min(
                suitable_workers,
                key=lambda w: w["task_queue_length"] + (1 if w["current_task_id"] else 0)
            )
            
            # 更新任务状态
            task["assignee_id"] = selected_worker["id"]
            task["status"] = "已分配"
            task["assigned_at"] = datetime.now().isoformat()
            await self.state_manager.update_task_state(task["id"], task, task["version"] - 1)
            
            # 通知组员和审查Agent
            await self.event_manager.publish(
                "events.leader.task_assigned",
                {"task": task, "assignee_id": selected_worker["id"]}
            )
            
            # 从队列移除
            self.task_queue.remove(task)
            logger.info(f"任务 {task['id']} 已分配给Agent {selected_worker['id']}")

    async def handle_critical_problem(self, request: Dict[str, Any]) -> Dict[str, Any]:
        """处理审查Agent上报的重大问题"""
        logger.critical(f"收到重大问题: 任务 {request['task_id']}, Agent {request['agent_id']}, {request['problem_message']}")
        await self.critical_problem_queue.put(request)
        return {"success": True}

    async def _process_critical_problem(self, problem: Dict[str, Any]) -> None:
        """处理单个重大问题"""
        task_id = problem["task_id"]
        agent_id = problem["agent_id"]
        
        # 1. 立即终止任务
        task = await self.state_manager.get_task_state(task_id)
        if task and task["status"] not in ["已完成", "已归档", "已终止"]:
            task["status"] = "已终止"
            task["termination_reason"] = problem["problem_message"]
            task["termination_time"] = datetime.now().isoformat()
            await self.state_manager.update_task_state(task_id, task, task["version"] - 1)
            logger.info(f"任务 {task_id} 已被紧急终止")
            
            # 2. 通知所有相关Agent
            await self.event_manager.publish(
                "events.leader.task_terminated",
                {"task_id": task_id, "reason": problem["problem_message"]}
            )
            
            # 3. 根据问题类型决策
            if problem["problem_type"] == "agent_offline":
                # Agent离线，尝试重新分配
                await self._reassign_task(task_id)
            elif problem["problem_type"] == "security_violation":
                # 安全违规，封禁Agent
                await self._ban_agent(agent_id)

    async def _reassign_task(self, task_id: str) -> None:
        """重新分配被终止的任务"""
        task = await self.state_manager.get_task_state(task_id)
        if not task:
            return
        
        # 重置任务状态
        task["status"] = "待重新分配"
        task["assignee_id"] = None
        task["retry_count"] = task.get("retry_count", 0) + 1
        await self.state_manager.update_task_state(task_id, task, task["version"] - 1)
        
        # 加入任务队列
        self.task_queue.append(task)
        logger.info(f"任务 {task_id} 已加入重新分配队列")

    async def _calculate_system_load(self) -> float:
        """计算系统整体负载"""
        all_agents = await self.state_manager.list_agents_by_type("worker")
        if not all_agents:
            return 0.0
        
        total_load = sum(
            agent["task_queue_length"] + (1 if agent["current_task_id"] else 0)
            for agent in all_agents
        )
        
        return total_load / len(all_agents)
```

```python
class ReviewerAgent(BaseAgent):
    def __init__(self, domain: str, detection_rules: Dict, *args, **kwargs):
        super().__init__(*args, agent_type="reviewer", **kwargs)
        self.domain = domain
        self.detection_rules = detection_rules
        self.active_monitors: Dict[str, asyncio.Task] = {}

    async def _init_state(self) -> Dict[str, Any]:
        base_state = await super()._init_state()
        return {
            **base_state,
            "domain": self.domain,
            "monitoring_task_count": 0,
            "detection_rule_count": sum(len(rules) for rules in self.detection_rules.values()),
        }

    async def _run_once(self) -> None:
        await self.update_state({
            "monitoring_task_count": len(self.active_monitors),
        })
        await asyncio.sleep(1)

    async def _on_task_assigned(self, event: Dict[str, Any]) -> None:
        """处理任务分配事件，开始监控"""
        task = event["task"]
        task_id = task["id"]
        worker_id = task["assignee_id"]
        
        # 只监控本领域的任务
        if task["task_type"] not in self.detection_rules and "global" not in self.detection_rules:
            return
        
        if task_id in self.active_monitors:
            logger.warning(f"已经在监控任务 {task_id}")
            return
        
        # 启动监控协程
        monitor_task = asyncio.create_task(self._monitor_task(task_id, worker_id))
        self.active_monitors[task_id] = monitor_task
        logger.info(f"开始监控任务 {task_id}，执行Agent: {worker_id}")

    async def _monitor_task(self, task_id: str, worker_id: str) -> None:
        """监控单个任务的执行过程"""
        try:
            # 建立与组员Agent的日志流连接
            async for log_entry in self.communication_manager.stream_to_agent(
                worker_id, "log_stream", {"task_id": task_id}
            ):
                # 分析日志
                problems = self._detect_problems(log_entry, task_id)
                
                for problem in problems:
                    # 问题分级
                    level = self._grade_problem(problem)
                    
                    # 上报问题
                    if level == "重大问题":
                        await self._report_critical_problem(task_id, worker_id, problem)
                    else:
                        await self._report_normal_problem(task_id, worker_id, problem, level)
                
                # 实时校验中间结果
                if log_entry["type"] == "intermediate_result":
                    await self._validate_intermediate_result(task_id, log_entry["data"])
        
        except Exception as e:
            # 连接断开判定为Agent离线
            logger.error(f"与Agent {worker_id} 的日志流连接断开: {str(e)}")
            await self._report_critical_problem(
                task_id, worker_id,
                {"type": "agent_offline", "message": f"Agent {worker_id} 意外离线"}
            )
        finally:
            # 清理监控
            if task_id in self.active_monitors:
                del self.active_monitors[task_id]
            logger.info(f"停止监控任务 {task_id}")

    def _detect_problems(self, log_entry: Dict[str, Any], task_id: str) -> List[Dict[str, Any]]:
        """根据检测规则检测问题"""
        problems = []
        task_type = self.state_manager.get_task_state(task_id)["task_type"]
        
        # 合并全局规则和任务类型专属规则
        rules = self.detection_rules.get(task_type, []) + self.detection_rules.get("global", [])
        
        for rule in rules:
            if self._match_rule(log_entry, rule):
                problems.append({
                    "rule_id": rule["id"],
                    "type": rule["type"],
                    "message": rule["message"].format(**log_entry),
                    "timestamp": log_entry["timestamp"],
                })
        
        return problems

    def _match_rule(self, log_entry: Dict[str, Any], rule: Dict[str, Any]) -> bool:
        """匹配单条检测规则"""
        if "keyword" in rule:
            return rule["keyword"].lower() in log_entry.get("message", "").lower()
        elif "regex" in rule:
            import re
            return re.search(rule["regex"], log_entry.get("message", "")) is not None
        elif "level" in rule:
            return log_entry.get("level", "INFO") == rule["level"]
        return False

    def _grade_problem(self, problem: Dict[str, Any]) -> str:
        """问题分级逻辑"""
        critical_types = {"agent_offline", "security_violation", "resource_exhausted"}
        serious_types = {"critical_error", "result_invalid", "timeout"}
        
        if problem["type"] in critical_types:
            return "重大问题"
        elif problem["type"] in serious_types:
            return "严重问题"
        else:
            return "一般问题"

    async def _report_critical_problem(self, task_id: str, agent_id: str, problem: Dict[str, Any]) -> None:
        """上报重大问题到领导Agent（紧急通道）"""
        logger.critical(f"检测到重大问题: {problem['message']}")
        await self.communication_manager.call_leader(
            "handle_critical_problem",
            {
                "task_id": task_id,
                "agent_id": agent_id,
                "problem_type": problem["type"],
                "problem_message": problem["message"],
                "timestamp": problem["timestamp"],
            },
            timeout=1.0  # 1秒超时
        )

    async def _report_normal_problem(self, task_id: str, agent_id: str, problem: Dict[str, Any], level: str) -> None:
        """上报一般/严重问题到综合Agent"""
        logger.info(f"检测到{level}: {problem['message']}")
        await self.event_manager.publish(
            "events.reviewer.problem_detected",
            {
                "task_id": task_id,
                "agent_id": agent_id,
                "level": level,
                "type": problem["type"],
                "message": problem["message"],
                "timestamp": problem["timestamp"],
            }
        )
```

```python
class WorkerAgent(BaseAgent):

        """执行单个任务"""
        try:
            # 更新任务状态为执行中
            await self.communication_manager.call_leader(
                "update_task_status",
                {"task_id": task["id"], "status": "执行中", "progress": 0.0}
            )
            
            # 执行任务逻辑
            result = await self._do_execute_task(task)
            
            # 任务完成
            await self.communication_manager.call_leader(
                "update_task_status",
                {
                    "task_id": task["id"],
                    "status": "已完成",
                    "progress": 100.0,
                    "result": result,
                }
            )
            
            logger.info(f"任务 {task['id']} 执行完成")
        
        except Exception as e:
            logger.error(f"任务 {task['id']} 执行失败: {str(e)}", exc_info=True)
            await self.communication_manager.call_leader(
                "update_task_status",
                {
                    "task_id": task["id"],
                    "status": "失败",
                    "progress": 0.0,
                    "error": {"message": str(e), "stack_trace": logger.format_exc()},
                }
            )
        
        finally:
            self.current_task = None
            await self.update_state({"current_task_id": None})

    async def _do_execute_task(self, task: Dict[str, Any]) -> Dict[str, Any]:
        """具体任务执行逻辑（可由子类重写）"""
        # 构建任务提示词
        prompt = f"""
        请执行以下任务：
        
        任务ID: {task['id']}
        任务类型: {task['task_type']}
        任务描述: {task['description']}
        预期输出: {task['expected_output']}
        参数: {json.dumps(task['parameters'], indent=2)}
        
        可用工具: {list(self.tools.keys())}
        如需使用工具，请按照指定格式调用。
        """
        
        # 调用大模型执行
        response = await self.llm.ainvoke(prompt)
        
        # 处理工具调用
        while hasattr(response, "tool_calls") and response.tool_calls:
            for tool_call in response.tool_calls:
                tool_name = tool_call["name"]
                tool_args = tool_call["args"]
                
                if tool_name not in self.tools:
                    raise ValueError(f"未知工具: {tool_name}")
                
                # 调用工具
                tool_result = await self.tools[tool_name](**tool_args)
                
                # 将工具结果返回给大模型
                response = await self.llm.ainvoke(
                    f"工具 {tool_name} 调用结果: {json.dumps(tool_result)}"
                )
        
        return {"content": response.content}

    async def _get_resource_usage(self) -> Dict[str, float]:
        """获取当前资源使用情况"""
        import psutil
        process = psutil.Process()
        return {
            "cpu_percent": process.cpu_percent(),
            "memory_percent": process.memory_percent(),
            "memory_mb": process.memory_info().rss / 1024 / 1024,
        }
```

```python
class StateManager:
    def __init__(self, redis_client: Redis):
        self.redis = redis_client

    async def get_agent_state(self, agent_id: str) -> Optional[Dict[str, Any]]:
        """获取Agent状态"""
        data = await self.redis.get(f"agent:{agent_id}")
        return json.loads(data) if data else None

    async def update_agent_state(self, agent_id: str, state: Dict[str, Any], expected_version: int) -> bool:
        """更新Agent状态（乐观锁）"""
        key = f"agent:{agent_id}"
        
        # 使用Redis WATCH实现乐观锁
        async with self.redis.pipeline() as pipe:
            try:
                await pipe.watch(key)
                current_data = await pipe.get(key)
                
                if not current_data:
                    return False
                
                current_state = json.loads(current_data)
                if current_state["version"] != expected_version:
                    return False
                
                # 执行更新
                await pipe.multi()
                await pipe.set(key, json.dumps(state))
                await pipe.execute()
                return True
            
            except Exception as e:
                logger.error(f"更新Agent状态失败: {str(e)}")
                return False
            
            finally:
                await pipe.unwatch()

    async def create_task_state(self, task: Dict[str, Any]) -> None:
        """创建任务状态"""
        await self.redis.set(f"task:{task['id']}", json.dumps(task))

    async def get_task_state(self, task_id: str) -> Optional[Dict[str, Any]]:
        """获取任务状态"""
        data = await self.redis.get(f"task:{task_id}")
        return json.loads(data) if data else None

    async def update_task_state(self, task_id: str, state: Dict[str, Any], expected_version: int) -> bool:
        """更新任务状态（乐观锁）"""
        key = f"task:{task_id}"
        
        async with self.redis.pipeline() as pipe:
            try:
                await pipe.watch(key)
                current_data = await pipe.get(key)
                
                if not current_data:
                    return False
                
                current_state = json.loads(current_data)
                if current_state["version"] != expected_version:
                    return False
                
                await pipe.multi()
                await pipe.set(key, json.dumps(state))
                await pipe.execute()
                return True
            
            except Exception as e:
                logger.error(f"更新任务状态失败: {str(e)}")
                return False
            
            finally:
                await pipe.unwatch()

    async def list_agents_by_type(self, agent_type: str) -> List[Dict[str, Any]]:
        """列出指定类型的所有Agent"""
        agent_keys = await self.redis.keys("agent:*")
        agents = []
        
        for key in agent_keys:
            data = await self.redis.get(key)
            if data:
                agent = json.loads(data)
                if agent["agent_type"] == agent_type:
                    agents.append(agent)
        
        return agents

    async def list_agents_by_type_and_status(self, agent_type: str, status: str) -> List[Dict[str, Any]]:
        """列出指定类型和状态的所有Agent"""
        agents = await self.list_agents_by_type(agent_type)
        return [a for a in agents if a["status"] == status]
```

```python
class CostManager:
    def __init__(self, redis_client: Redis):
        self.redis = redis_client
        self._load_pricing()
        self.tokenizers = {}

    def _load_pricing(self) -> None:
        """加载定价数据"""
        self.pricing = {
            "models": {
                "deepseek-chat": {"input": 0.001/1000, "output": 0.002/1000},
                "gpt-3.5-turbo": {"input": 0.0005/1000, "output": 0.0015/1000},
                "gpt-4o": {"input": 0.005/1000, "output": 0.015/1000},
            },
            "tools": {
                "serper_search": 0.001,
                "code_interpreter": 0.01,
            },
            "resources": {
                "cpu": 0.001/60,
                "gpu": 0.01/60,
            }
        }
        
        # 从Redis加载自定义定价
        custom_pricing = await self.redis.get("cost:pricing")
        if custom_pricing:
            self.pricing.update(json.loads(custom_pricing))

    def count_tokens(self, text: str, model: str) -> int:
        """精确计算Token数量"""
        if model not in self.tokenizers:
            try:
                import tiktoken
                self.tokenizers[model] = tiktoken.encoding_for_model(model)
            except:
                # 降级使用gpt-3.5-turbo分词器
                import tiktoken
                self.tokenizers[model] = tiktoken.encoding_for_model("gpt-3.5-turbo")
        
        return len(self.tokenizers[model].encode(text))

    async def estimate_task_cost(self, task_description: str, task_type: str) -> Dict[str, float]:
        """混合成本预估算法"""
        # 1. 历史数据相似度预估（60%权重）
        history_estimate = await self._estimate_by_history(task_description)
        
        # 2. 大模型辅助预估（40%权重）
        llm_estimate = await self._estimate_by_llm(task_description, task_type)
        
        # 3. 综合计算
        if history_estimate > 0 and llm_estimate > 0:
            total = history_estimate * 0.6 + llm_estimate * 0.4
        elif history_estimate > 0:
            total = history_estimate
        else:
            total = llm_estimate
        
        # 4. 新任务增加30%不确定性缓冲
        if history_estimate == 0:
            total *= 1.3
        
        return {
            "total": round(total, 4),
            "model": round(total * 0.7, 4),
            "tool": round(total * 0.2, 4),
            "resource": round(total * 0.1, 4),
        }

    async def _estimate_by_history(self, task_description: str) -> float:
        """基于历史相似度预估"""
        history = await self.redis.lrange("cost:history", 0, -1)
        if not history:
            return 0.0
        
        records = [json.loads(r) for r in history]
        descriptions = [r["description"] for r in records]
        costs = [r["cost"] for r in records]
        
        # TF-IDF相似度计算
        from sklearn.feature_extraction.text import TfidfVectorizer
        from sklearn.metrics.pairwise import cosine_similarity
        
        vectorizer = TfidfVectorizer()
        all_texts = descriptions + [task_description]
        tfidf_matrix = vectorizer.fit_transform(all_texts)
        
        similarities = cosine_similarity(tfidf_matrix[-1:], tfidf_matrix[:-1]).flatten()
        top_indices = similarities.argsort()[-3:][::-1]
        top_costs = [costs[i] for i in top_indices if similarities[i] > 0.2]
        
        return sum(top_costs) / len(top_costs) if top_costs else 0.0

    async def _estimate_by_llm(self, task_description: str, task_type: str) -> float:
        """大模型辅助预估"""
        prompt = f"""
        预估完成以下任务的大模型调用成本（单位：人民币元）：
        
        任务描述：{task_description}
        任务类型：{task_type}
        
        参考定价：
        - DeepSeek V3: 输入¥0.001/千Token，输出¥0.002/千Token
        - 工具调用：平均¥0.005/次
        
        只返回一个数字，不要其他解释。
        """
        
        response = await self.llm.ainvoke(prompt)
        try:
            return float(response.content.strip())
        except:
            return 0.0
```

## 10. 注意事项
### 10.1 开发注意事项
1. **严格遵循单一职责原则**：每个Agent和模块只负责自己的核心职责，避免职责重叠
2. **所有操作必须实现幂等性**：确保重复执行不会产生副作用，这是分布式系统的基础要求
3. **异常处理全覆盖**：所有可能抛出异常的地方都要有异常处理，避免单个异常导致整个系统崩溃
4. **日志记录规范**：所有关键操作都要有详细的日志记录，包含时间、操作人、操作内容、结果等信息
5. **版本化设计**：所有接口、数据模型、配置都要支持版本化，保证向后兼容
6. **测试驱动开发**：为所有核心功能编写单元测试和集成测试，保证代码质量
7. **代码评审**：所有代码必须经过评审才能合并，确保代码符合规范和设计要求

### 10.2 部署注意事项
1. **环境隔离**：开发、测试、生产环境严格隔离，避免互相影响
2. **配置管理**：使用配置中心管理所有配置，不要硬编码在代码中
3. **资源限制**：为每个Agent和服务设置合理的资源限制（CPU、内存、磁盘），防止资源耗尽
4. **健康检查**：实现健康检查接口，便于监控系统检测服务状态
5. **滚动更新**：采用滚动更新方式部署，避免服务中断
6. **备份策略**：制定完善的数据备份策略，定期备份所有重要数据
7. **网络安全**：配置防火墙和网络访问控制列表，只开放必要的端口

### 10.3 运维注意事项
1. **监控全覆盖**：监控系统的所有关键指标，包括性能、可用性、成本、质量等
2. **告警分级**：将告警分为不同等级，不同等级的告警采用不同的通知方式和处理流程
3. **应急预案**：制定完善的应急预案，定期进行演练，确保在故障发生时能够快速响应
4. **容量规划**：定期进行容量评估，提前规划资源扩容
5. **变更管理**：所有系统变更都要有记录和审批流程，避免未经测试的变更上线
6. **问题复盘**：每次故障发生后都要进行复盘，分析根本原因，制定改进措施
7. **文档维护**：及时更新技术文档和运维手册，确保文档与实际系统一致

### 10.4 安全注意事项
1. **身份认证**：所有API和服务都必须进行身份认证，禁止匿名访问
2. **权限控制**：遵循最小权限原则，每个用户和服务只拥有完成其任务所必需的权限
3. **数据加密**：所有敏感数据在传输和存储时都必须加密
4. **输入验证**：对所有外部输入进行严格验证，防止注入攻击
5. **安全审计**：定期进行安全审计，发现并修复安全漏洞
6. **漏洞管理**：及时修复已知的安全漏洞，保持系统和依赖库的最新版本
7. **员工培训**：定期对员工进行安全培训，提高安全意识

2. **联邦学习与隐私计算**：在不共享原始数据的前提下实现跨组织协作
3. **跨组织安全协作与联盟链**：基于联盟链实现跨组织的可信协作和自动化结算
4. **自主进化与自我改进**：系统能够自动评估自己的表现，发现问题并自我改进
5. **大规模多智能体系统支持**：支持成千上万个Agent同时运行，处理超大规模任务

# 多智能体协作系统交互设计专项讨论
基于之前的技术架构和生产实践痛点，聚焦**三类核心用户**的**六大核心流程**，解决现有多Agent系统普遍存在的"黑盒化"、"不可控"、"难调试"三大交互顽疾。

---

## 一、用户角色与核心交互场景
### 1.1 三类核心用户画像
| 用户角色 | 核心目标 | 典型使用频率 | 技术背景 | 核心痛点 |
|---------|----------|--------------|----------|----------|
| **业务用户** | 提交任务、获取结果、监控进度 | 高频 | 非技术 | 系统黑盒、进度不透明、结果不可控 |
| **系统管理员** | 监控系统状态、处理异常、配置管理 | 中频 | 技术 | 问题定位难、故障响应慢、批量操作繁琐 |
| **开发者** | 调试Agent、优化规则、扩展功能 | 高频 | 技术 | 缺乏调试工具、日志分散、难以复现问题 |

### 1.2 六大核心交互流程
所有交互设计围绕以下流程展开，确保每个步骤都有清晰的反馈和控制入口：
1. 任务提交与参数配置
2. 实时执行监控与进度追踪
3. 阶段评审与人工干预
4. 问题告警与处理闭环
5. 成本可视化与控制
6. 结果查看与反馈迭代

## 二、核心流程交互设计
### 2.1 任务提交与参数配置交互
**设计目标**：降低非技术用户使用门槛，同时满足技术用户的精细化配置需求。

#### 2.1.1 双模式任务提交
- **简易模式**（业务用户）：
    - 自然语言输入框，支持拖拽上传附件
    - 智能提示：根据输入内容自动补全任务类型、预期输出格式
    - 一键提交：系统自动填充默认参数
    - 成本预估预览：提交前显示预估成本范围和执行时间

- **高级模式**（技术用户）：
    - 可视化任务分解器：拖拽式定义子任务和依赖关系
    - 角色分配：手动指定每个子任务的执行Agent
    - 高级参数配置：成本上限、最大重试次数、评审节点、超时时间
    - 模板保存：将常用任务配置保存为模板，一键复用

#### 2.1.2 关键交互细节
- **成本预估实时更新**：用户输入任务描述时，实时显示预估成本和执行时间
- **参数校验**：实时校验参数合法性，给出明确的错误提示和修正建议
- **依赖关系可视化**：用有向图展示子任务之间的依赖关系，支持拖拽调整
- **冲突检测**：自动检测参数冲突和依赖循环，给出解决方案

### 2.2 实时执行监控与进度追踪交互
**设计目标**：打破系统黑盒，让用户清晰了解任务执行的每一步。

#### 2.2.1 全局任务看板
- **任务状态卡片**：每个任务用卡片展示，包含任务ID、类型、状态、进度、当前执行Agent、已消耗成本
- **状态颜色编码**：
    - 蓝色：等待中
    - 绿色：执行中
    - 黄色：待评审/待修正
    - 红色：失败/已终止
    - 灰色：已完成/已归档
- **批量操作**：支持批量暂停、恢复、终止任务
- **筛选与搜索**：按状态、类型、时间、创建人等维度筛选任务

#### 2.2.2 任务详情页（核心交互）
采用**三栏式布局**，全面展示任务执行信息：
- **左侧栏**：任务基本信息、执行进度条、成本消耗、关键时间节点
- **中间栏**：**执行时间线**，按时间顺序展示所有执行步骤：
    - 每个步骤显示：执行Agent、开始/结束时间、耗时、状态
    - 可展开查看步骤详情：输入、输出、工具调用记录、日志
    - 异常步骤用红色高亮，显示错误信息和堆栈
- **右侧栏**：实时日志流、问题告警、相关任务推荐

#### 2.2.3 关键交互细节
- **进度颗粒度**：精确到步骤级，而不是任务级
- **实时更新**：所有状态和进度实时更新，无需刷新页面
- **执行回放**：支持任务执行过程的回放，按步骤查看执行情况
- **Agent状态悬浮窗**：鼠标悬停在Agent名称上，显示该Agent的当前负载、历史表现等信息

### 2.3 阶段评审与人工干预交互
**设计目标**：实现无缝人机协同，让人工干预自然融入自动化流程。

#### 2.3.1 阶段评审交互
- **评审通知**：到达评审节点时，通过站内信、邮件、短信等方式通知相关人员
- **评审工作台**：
    - 左侧：中间结果预览（支持Markdown、JSON、图片等多种格式）
    - 中间：评审标准和评分表
    - 右侧：评审意见输入框、修正建议
- **一键操作**：
    - 通过：自动继续执行下一阶段
    - 不通过：输入修正意见，自动创建修正任务
    - 转人工：将任务转交给指定人员处理

#### 2.3.2 人工干预交互
- **全局干预按钮**：在任务详情页的显著位置提供"暂停"、"恢复"、"终止"按钮
- **任务接管**：
    - 点击"接管"按钮，进入人工编辑模式
    - 可以修改任务参数、中间结果、执行流程
    - 完成后点击"交回"，系统自动继续执行后续步骤
- **任务转交**：支持将任务转交给其他用户或Agent处理

#### 2.3.3 关键交互细节
- **干预记录**：所有人工干预操作都有详细记录，包含操作人、时间、操作内容、原因
- **无缝衔接**：人工干预后，系统能够自动从干预点继续执行，无需从头开始
- **批量评审**：支持同时评审多个任务的同一阶段
- **评审模板**：支持自定义评审模板，统一评审标准

### 2.4 问题告警与处理闭环交互
**设计目标**：确保问题及时发现、快速响应、有效解决。

#### 2.4.1 分级告警体系
- **告警级别与通知方式**：
    - 一般问题：站内信，每日汇总通知
    - 严重问题：站内信+邮件，实时通知
    - 重大问题：站内信+邮件+短信+电话，立即通知
- **告警聚合**：将相同类型、相同任务的告警聚合，避免告警风暴
- **告警抑制**：当系统发生大面积故障时，抑制次要告警，突出核心问题

#### 2.4.2 问题处理工作台
- **告警列表**：按级别和时间排序，显示告警ID、任务ID、问题类型、发生时间、状态
- **问题详情页**：
    - 问题基本信息：类型、级别、发生时间、影响范围
    - 相关上下文：任务执行日志、错误堆栈、相关指标
    - 处理建议：系统自动给出的可能解决方案
    - 处理记录：所有处理操作的记录
- **一键处理**：
    - 重试：一键重试失败的任务
    - 重新分配：一键将任务重新分配给其他Agent
    - 转人工：一键将问题转交给指定人员处理

#### 2.4.3 关键交互细节
- **告警溯源**：点击告警可以直接跳转到对应的任务详情页和执行步骤
- **处理闭环**：每个问题都有明确的状态（待处理、处理中、已解决、已忽略）
- **根因分析**：问题解决后，引导用户填写根因分析和改进措施
- **知识库关联**：自动关联历史相似问题和解决方案

### 2.5 成本可视化与控制交互
**设计目标**：让用户清晰了解成本构成，有效控制成本支出。

#### 2.5.1 成本仪表盘
- **全局成本统计**：总支出、今日支出、本月支出、预算剩余
- **成本趋势图**：按天/周/月展示成本变化趋势
- **成本构成分析**：饼图展示模型成本、工具成本、资源成本的占比
- **Top N高成本任务**：列出消耗成本最高的任务

#### 2.5.2 任务级成本明细
- **实时成本追踪**：任务执行过程中实时显示已消耗成本和剩余预算
- **成本明细**：按步骤、按Agent、按模型展示详细的成本消耗
- **成本对比**：对比预估成本和实际成本，显示差异和差异率
- **成本预警**：当成本达到预警阈值时，在界面上显著提示

#### 2.5.3 成本控制交互
- **预算管理**：支持按用户、按项目、按任务类型设置预算
- **成本上限设置**：每个任务可以设置单独的成本上限
- **自动终止**：当成本达到上限时，自动终止任务并通知用户
- **成本优化建议**：系统自动分析成本构成，给出优化建议

### 2.6 结果查看与反馈迭代交互
**设计目标**：方便用户查看和使用结果，同时收集反馈优化系统。

#### 2.6.1 结果展示
- **多格式支持**：支持Markdown、JSON、PDF、Excel、图片等多种格式的结果展示
- **结果下载**：一键下载结果文件
- **结果分享**：生成分享链接，支持设置有效期和访问权限
- **结果对比**：支持对比同一任务的多次执行结果

#### 2.6.2 反馈与迭代
- **结果评分**：用户可以对结果进行1-5星评分
- **反馈输入**：用户可以输入详细的反馈意见和改进建议
- **自动重执行**：根据用户反馈，一键重新执行任务
- **反馈闭环**：系统将用户反馈转化为训练数据，不断优化模型和策略

## 三、关键界面设计原则
### 3.1 状态优先原则
所有界面都应该**首先展示状态**，让用户一眼就能知道"现在发生了什么"。
- 任务列表页：首先展示任务状态和进度
- 任务详情页：首先展示任务整体状态和关键指标
- 系统监控页：首先展示系统整体健康状态

### 3.2 渐进式信息披露原则
根据用户的需求逐步展示信息，避免信息过载。
- 默认展示核心信息，详细信息通过折叠面板或弹窗展示
- 提供"更多"按钮，让用户可以按需查看更多细节
- 不同用户角色看到不同粒度的信息

### 3.3 一致性原则
保持整个系统交互的一致性，降低用户学习成本。
- 统一的颜色编码：相同状态使用相同的颜色
- 统一的操作按钮：相同功能使用相同的按钮样式和位置
- 统一的术语：整个系统使用相同的术语描述相同的概念

### 3.4 可操作性原则
确保所有关键操作都**一键可达**，减少用户的操作步骤。
- 常用操作放在界面的显著位置
- 支持快捷键操作
- 提供批量操作功能

### 3.5 反馈原则
所有用户操作都应该有**即时、明确的反馈**。
- 按钮点击后显示加载状态
- 操作成功/失败给出明确的提示
- 长时间运行的操作显示进度条

### 跨框架多智能体协作模块汇总

#### 一、 核心问题与设计目标

**核心问题**：单一多智能体框架（如CrewAI、AutoGen）无法在所有任务场景中都达到最优。不同框架在任务编排、工具生态、对话协作、代码执行等方面各有优势，形成“孤岛效应”。用户在跨框架使用时面临接口不统一、状态不可通、成本难统计、协作效率低等痛点。

**设计目标**：
1.  **统一调度**：屏蔽不同框架的底层差异，提供一个标准化的任务分发与执行入口。
2.  **全局一致**：确保跨框架、跨Agent的任务状态、中间结果和全局信息的一致性。
3.  **高效通信**：建立跨框架的通信总线，支持Agent间的点对点、发布/订阅等多种模式。
4.  **成本可观测**：统一计量跨框架任务执行所产生的各类成本（Token、工具、计算资源）。
5.  **身份与信誉互通**：建立一套独立于任一框架的Agent身份与信誉体系，实现跨框架的信任与协作。

#### 二、 总体架构设计

该模块的核心架构是一个**“主框架+子框架”的分层、松耦合集成架构**。

*   **主框架 (Orchestrator)**：通常选用 **CrewAI** 作为全局任务编排引擎。其优势在于任务分解、角色定义和流程控制能力强，适合扮演“总指挥”的角色。
*   **子框架 (Executors)**：根据子任务的特定需求，动态调度给最合适的框架执行。
   *   **LangChain**：负责信息检索、RAG问答、复杂工具链调用。
   *   **AutoGen**：负责代码编写、执行、调试以及需要多轮讨论的复杂任务。
   *   **MetaGPT**：负责完整的软件工程项目开发（系统设计、编码、测试）。
   *   **OpenAI Agents**：负责处理简单的、需要快速响应的工具调用任务。

**架构图（逻辑视图）**：

```mermaid
graph TD
    User[用户/请求] --> Orchestrator[主框架: CrewAI <br> (任务分解与调度)]

    subgraph SubFrameworks [子框架执行层]
        Orchestrator -- 任务分发 --> LangChain[LangChain <br> (信息检索/RAG)]
        Orchestrator -- 任务分发 --> AutoGen[AutoGen <br> (代码/数据分析)]
        Orchestrator -- 任务分发 --> MetaGPT[MetaGPT <br> (软件开发)]
        Orchestrator -- 任务分发 --> OpenAI[OpenAI Agents <br> (简单工具调用)]
    end

    subgraph CrossCutting [横向支撑服务]
        Blackboard[全局黑板 <br> (状态共享)]
        EventBus[事件总线 <br> (跨框架通信)]
        Telemetry[统一计量服务 <br> (成本/可观测性)]
        Registry[Agent注册中心 <br> (身份/信誉)]
    end

    LangChain -.-> Blackboard
    AutoGen -.-> Blackboard
    LangChain -.-> EventBus
    AutoGen -.-> EventBus
    
    Orchestrator --> Telemetry
    SubFrameworks --> Telemetry
    
    Orchestrator --> Registry
    SubFrameworks --> Registry
```

#### 三、 核心功能与实现机制

1.  **统一任务调度与适配**
   *   **适配器模式**：为每个子框架实现一个标准的`BaseAgentAdapter`接口，封装`execute`, `cancel`, `get_status`等方法，将框架特有的API统一化。
   *   **消息队列解耦**：主框架与子框架之间通过 **RabbitMQ** 等消息队列进行通信。主框架将子任务序列化后发送到对应框架的任务队列，子框架执行完成后将结果发回结果队列。这种松耦合设计保证了各框架的独立性和可扩展性。

2.  **跨框架通信与状态同步**
   *   **全局黑板模式**：使用 **Redis** 实现一个全局黑板（`GlobalBlackboard`），作为所有Agent共享的工作区。任何Agent都可以将中间结果、状态变更写入黑板，其他Agent通过订阅机制获取实时通知，实现状态最终一致性。
   *   **统一消息格式**：定义基于 **Protocol Buffers** 的标准消息格式（`TaskMessage`, `ResultMessage`, `AgentMessage`），确保跨语言、跨框架的信息交换无歧义。
   *   **事件驱动架构**：构建全局事件总线（`EventBus`），所有关键动作（任务完成、状态变更、异常发生）都发布为事件，实现组件间的完全解耦。

3.  **统一成本可观测性系统（关键创新点）**
   *   **Sidecar代理**：在每个Agent运行时环境旁部署一个独立的Sidecar代理进程。该代理透明拦截Agent对LLM API的调用，通过`tiktoken`等库实时计量Token消耗。
   *   **多维计量模型**：将计量维度从单一的LLM Token扩展到 **MCP工具调用次数、向量检索计算单元（CU）、云函数执行时长** 等多种资源类型。
   *   **平台信用点**：将所有资源消耗统一折算为“平台信用点”，为用户提供一个统一的账单和成本视图，彻底解决跨框架成本统计难题。
   *   **智能降本**：代理层集成了**请求合并、语义缓存、模型路由决策引擎**等降本技术。

4.  **Agent身份与信誉体系**
   *   **去中心化身份（DID/VC）**：为每个Agent创建可验证的数字身份，使其行为可以跨框架、跨平台被追溯和验证。
   *   **扩展A2A协议**：基于A2A协议的`Agent Card`进行扩展，增加`reputation_weight`、`cost_estimate`、`proof_of_execution`等字段，使信誉和成本信息成为协作协商的标准部分。
   *   **贝叶斯平均信誉算法**：综合任务成功率、用户评分、响应速度等因子，采用贝叶斯平均法计算Agent信誉分，避免新Agent因样本少而评分失准。信誉分直接影响任务竞标排序和能力市场推荐权重。

5.  **协议适配与生态兼容**
   *   **协议适配层**：采用插件化架构构建协议适配服务，支持 **A2A（Agent-to-Agent）** 和 **MCP（Model Context Protocol）** 两种主流协议。该层负责协议编解码、消息格式转换（如A2A与MCP间的转换）和版本兼容。
   *   **处理框架特异性**：在标准协议中定义`x-framework-specific`扩展字段，用于传递如CrewAI的角色扮演机制或LangGraph的状态机等框架独有的高级特性，避免“削足适履”。

#### 四、 关键挑战与解决方案汇总

| 关键挑战 | 解决方案 |
| :--- | :--- |
| **框架版本迭代快，适配层维护难** | 1. 最小依赖原则，每个Driver代码控制在500行内。<br>2. 开源Driver适配层，鼓励社区贡献。<br>3. 客户端内置版本管理器，支持多版本框架并行。 |
| **跨框架成本统一计量** | 1. Sidecar代理扩展多维度计量（Token、工具、CU等）。<br>2. 建立“平台信用点”统一换算模型。<br>3. 成本归因看板，支持按Agent、任务、工具多维度聚合展示。 |
| **跨框架Agent身份与信誉** | 1. 引入DID/VC，建立全局唯一身份。<br>2. 扩展A2A `Agent Card`，内嵌信誉凭证。<br>3. 信誉分作为市场搜索排序核心权重，形成激励机制。 |
| **框架特定功能与通用标准矛盾** | 1. 在标准协议中定义`x-framework-specific`扩展字段传递原生参数。<br>2. 提供“高级模式”绕过抽象层，直接操作框架原生配置。<br>3. 积极参与标准制定，将普适特性回馈至社区。 |
| **协议分裂风险（A2A vs. 其他）** | 1. 协议适配层采用插件化架构，支持动态加载新协议编解码器。<br>2. 定位为“协议路由器”，提供跨标准互操作能力，强化自身价值。 |

#### 五、 总结：该模块的价值与创新点

1.  **从“框架绑定”到“框架无关”**：通过适配层和标准协议，解耦了上层应用与底层框架，使用户和开发者可以自由选择、切换、组合不同框架，是AI Agent生态走向成熟的关键一步。
2.  **从“成本黑盒”到“透明可控”**：创新的Sidecar代理和统一信用点模型，首次实现了跨框架、跨模型、跨服务的细粒度成本可观测性，解决了企业级应用落地的最核心痛点之一。
3.  **从“单点工具”到“协同网络”**：通过全局黑板、事件总线和A2A/MCP协议，将孤立的Agent节点连接成一个可协作、可委托、可信任的智能体网络，产生了“1+1>2”的协同效应。
4.  **从“开发者专享”到“平台化生态”**：通过构建身份、信誉、能力市场等横向服务，该模块不仅仅是技术整合，更是为构建一个繁荣的、自进化的AI Agent经济生态奠定了技术基石。
