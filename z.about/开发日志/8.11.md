## 第四阶段：工程化与自动化

### 提交 4 — `f08d8f4`（4 项）

**目标：消除手动启动步骤，修复配置漂移。**

#### 4.1 新增 client/.gitignore
- 问题：`client/` 下无独立 `.gitignore`，`node_modules/`、`dist/`、`.vite/` 依赖根 `.gitignore` 兜底
- 修复：新建 `client/.gitignore`，包含依赖、构建产物、环境变量、IDE 和系统文件

#### 4.2 Go 成本计算接入定价表
- 问题：`cost_calculator.go` 的 `calcLLMCost()` 写死 `float64(inputTokens+outputTokens) * 0.0001`，完全忽略已有的 `pricingTable` 和 `pkg/pricing/model_pricing.go`
- 修复：改为查表计算，公式 `(input/1M * price.Input) + (output/1M * price.Output)`，未知模型回退默认定价

#### 4.3 隔离 Go 项目于 turbo 之外
- 问题：`pnpm-workspace.yaml` 声明 `server/*`，包含 Go 项目。`turbo build` 会尝试对其执行 `build` 脚本并失败
- 修复：`server/*` 改为 `server/api-gateway`，仅 NestJS 项目进入 workspace

#### 4.4 Electron 启动时自动拉起服务
- 问题：Python 服务（CrewAI + LangGraph）和 Sidecar 代理需要手动启动
- 修复：
  - `index.ts` 新增 `spawnPythonServices()`：使用 `child_process.spawn` 启动 `start_services.py`，stdout/stderr 转发到主进程日志
  - 新增 `startSidecarIfConfigured()`：当 `SIDECAR_TARGET_URL` + `SIDECAR_API_KEY` 环境变量存在时自动启动 TokenProxy
  - `app.whenReady()` 中依次执行：注册 IPC → 拉起 Python → 启动 Sidecar → 创建窗口
  - `app.on('will-quit')` 中调用 `cleanupServices()` 优雅关闭

## 第五阶段：核心链路打通

### 提交 5 — `c5a82cc`（3 项）

**目标：修复"Agent 操作系统"最核心的缺失。**

#### 5.1 前端地址环境变量化
- 问题：4 个文件中硬编码 `http://localhost:` 地址，无法按环境切换
- 修复：
  - `env.ts` 新增 5 个服务地址常量：`API_BASE`、`CREWAI_SERVICE_URL`、`LANGGRAPH_SERVICE_URL`、`DEPLOY_SERVICE_URL`、`OLLAMA_URL`
  - 全部从 Vite 环境变量读取，带默认值
  - `client.api.ts`、`pythonService.ts`、`Deployment.tsx`、`agent-config.ts`、`agentRegistry.store.ts` 共 5 个文件的硬编码全部替换
  - `client/.env` 补全新增变量

#### 5.2 实现任务执行管道
- 问题：`TaskExecutor.createTask()` 只创建任务对象，不调用 Agent endpoint——这是"Agent 生命周期管理"的核心缺失
- 修复：
  - 新增 `executeStep()` 方法：向 Agent endpoint 发送 POST 请求，解析 SSE 流（`data: {...}`），实时发出 `chunk` 事件，完成后回填 `step.output` + 成本
  - 新增 `executeTask()` 方法：按序执行所有 pending 步骤，每个步骤前检查预算熔断器状态
  - `createTask()` 的 IPC handler 改为创建后异步调用 `executeTask()`
  - 支持 CrewAI（`:8001/api/crewai/pipeline`）和 LangGraph（`:8002/api/langgraph/execute`）两种框架

#### 5.3 验证社区页面前后端 API 一致性
- 验证 `post.api.ts` 的路由和方法与 NestJS `PostController` 完全匹配
- 验证响应格式（`PostListResponse`）与 `PostService.list()` 返回结构一致
- 结论：`VITE_USE_MOCK=false` 即可一键切换到真实 API，无需代码改动
