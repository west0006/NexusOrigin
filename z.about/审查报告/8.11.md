## 📊 一、当前项目状态

### 1.1 总体定位

**枢元 NexusOrigin** 定位为「框架无关的 AI Agent 生命周期管理操作系统」。目标用户分两轨：**普通用户**（零代码使用AI Agent）和**开发者**（部署/开发/MCP工具上架）。项目处于 **MVP 向 V1.0 过渡阶段**——架构骨架完整，但多条核心链路未打通。

### 1.2 各层实现状态

| 层级 | 技术栈 | 完成度 | 说明 |
|------|--------|--------|------|
| **前端 UI** | React 19 + Vite + Zustand + Recharts + Tailwind | 🟢 85% | 14 个页面全部有 UI 实现，设计系统完整（C 常量 + CSS 变量） |
| **Electron 壳** | Electron 31 + IPC | 🟡 60% | 窗口创建/IPC 注册完成，但 Python 服务/Sidecar 未在启动时自动拉起 |
| **中枢调度器** | TypeScript (主进程) | 🟡 50% | 能力注册表 + 任务执行器 + 预算熔断器写好了，但**不真正调用 Agent endpoint** |
| **API 网关** | NestJS 10 + Prisma 5 | 🟡 55% | 16 个数据模型 + 模块脚手架就绪，但大部分 Controller 的 CRUD 逻辑未实现 |
| **Python Agent 服务** | Flask + Ollama | 🟢 75% | CrewAI 和 LangGraph 两个服务可独立运行，SSE 流式输出正常 |
| **Go 遥测服务** | Gin + GORM + Redis | 🟡 50% | 框架搭好、路由注册完毕，具体业务逻辑（Token 计数、预算检查）多是骨架 |
| **Go 部署服务** | Gin | 🟡 40% | Driver 接口定义了，三个 Driver 的 Install/Start/Stop 调的是不存在的 CLI 命令 |
| **Docker 编排** | Docker Compose | 🟢 80% | 开发/生产两套 compose，Nginx 反代，健康检查配置完整 |
| **CI/CD** | GitHub Actions | 🟢 70% | Lint + Docker build/push 流水线就绪 |

### 1.3 能跑通的功能

- ✅ 前端页面导航、三栏布局、聚焦面板、命令面板
- ✅ 用户注册/登录 UI + 新手引导流程
- ✅ 社区帖子列表、详情、评论的 UI（用 Mock 数据）
- ✅ Agent 注册表单 + 列表展示
- ✅ 能力市场卡片列表 + 本地安装状态
- ✅ 成本中心仪表盘 + 预算编辑
- ✅ Python CrewAI/LangGraph 服务可独立启动，通过 Ollama 调用 `qwen2.5-coder:1.5b` 完成流式对话
- ✅ 部署向导的环境检测 + 步骤式 UI

### 1.4 跑不通的关键链路

- ❌ 中枢调度器创建任务后，**不会真正调用 Agent 的 HTTP endpoint**——`TaskExecutor.createTask` 只是建对象
- ❌ 任务市场的"发布任务→Agent竞标→执行→交付"闭环未打通
- ❌ 社区 API 大多返回 Mock 数据（`USE_MOCK = true` 硬编码）
- ❌ Go deploy-service 调用的 `crewai run` / `langgraph serve` CLI 命令不存在
- ❌ Sidecar Token 代理（端口 18790）未在 Electron 启动时自动拉起
- ❌ 前端直接 `fetch('http://localhost:8082')` 调用部署服务，但该服务正常运行需要 Go 编译+Pipeline 推送镜像

## 🚀 三、后续可优化方向

### 3.1 关键链路打通（P0 — 演示前必须完成）

| 方向 | 具体措施 |
|------|----------|
| **打通任务执行链路** | `TaskExecutor.createTask` 中增加 `executeStep`：向 Agent endpoint 发 HTTP 请求 → 解析 SSE 流 → 回填 step output。为 SSE 流式事件转发到渲染进程 |
| **统一 Mock 开关** | 将散布在各页面的 `USE_MOCK` 提升为全局配置（环境变量或 store），支持一键切换到真实 API |
| **修复 Python 依赖** | `requirements.txt` 补充 `crewai`, `langgraph`, `langchain-ollama`, `langchain-community`；或直接改用 `start_services.py` 中 `subprocess` 管理的 Flask 方案 |
| **启动时自动拉起 Python 服务** | Electron 主进程 `app.whenReady()` 中 `spawn` Python 服务 + Sidecar 代理，退出时 `cleanup` |
| **补充 NestJS Controller 实现** | 至少实现 `POST /posts`, `GET /posts`, `POST /comments` 等社区核心 API |

### 3.2 架构优化（P1）

| 方向 | 具体措施 |
|------|----------|
| **修复部署服务 Driver** | 将 `crewai run` / `langgraph serve` 改为实际可用的 Python 子进程调用（直接调 `crewai_server.py` 和 `langgraph_server.py`），或直接移除 Driver 层改为调用 Python 服务 |
| **Sidecar 支持流式响应** | `TokenProxyServer` 中解析 `stream: true` 的 SSE 响应，累加所有 chunk 的 content 后再计 Token |
| **统一样式方案** | 全部收敛到 Tailwind + CSS 变量，删除内联 `style` 中对 `C` 的引用，统一 `C.textBody` 和 `--nexus-text-base` |
| **安全加固** | `.env` 加入 `.gitignore`，JWT Secret 强制从环境变量读取无 fallback，API Key 字段实现 AES 加密存储 |
| **组件拆分** | `Dashboard.tsx` 拆出 `ApiKeyPanel`、`UsageChart`、`StatsCards`；`Community.tsx` 拆出 `PostList`、`PostDetail` |

## 📌 四、总结

**项目骨架完整、设计文档质量极高**（五层架构 + 交互规范 + 业务闭环全部有详细文档），但 **代码实现约 50-60% 完成度**。核心短板在于：

1. **任务执行链路是空的**——调度器不调 Agent，这是"Agent 操作系统"最致命的问题
2. **Mock 数据硬编码**——前后端未真正联调，大量 `USE_MOCK = true`
3. **Python 依赖缺失**——任何人按 README 搭建都会失败
4. **Go 服务 Driver 不可用**——调的 CLI 不存在

如果目标是比赛演示，建议优先级：**打通任务执行 → 修复 Python 依赖 → 补充 NestJS 社区 API → 自动拉起服务 → 关掉 Mock**。其他优化（组件拆分、样式统一、精确 Token）可以在 P2 阶段渐进式推进。
